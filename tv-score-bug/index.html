The idea

My numbers, on the broadcast

I run a college football power-ratings site (ycpr.vercel.app) with my own projected spreads and totals, locked before kickoff, plus a log of every bet and pool pick. On Saturdays I was watching the game on TV with a laptop open to check it all.

The goal: put that information on the TV itself without leaving YouTube TV. I didn't want a separate app to switch to. I wanted a see-through layer on top of the picture, like a network's score bug, controlled from my phone because a TV remote can't reach an overlay.

  • Works over any app: the TV remote still controls the show underneath.
  • Shows my locked projections next to Vegas, and my bets graded live.
  • A spoiler delay holds scores back so the bug never beats the stream.
  • No paid data: ESPN's public scoreboard and Sleeper's public API, cached at the edge.
  • Everything visual is a web page, so updates deploy like a website.

Process

How I built it

  1. Scoped the approach

    Compared options and settled on an Android “display over other apps” window (the approach the open-source PiPup uses) holding a transparent web page, with a phone page as the remote.

  2. Built the web overlay inside the existing site

    Added /overlay and /overlay/control to the React app and reused its team data, logos, lines and locks. The site was at 11 of Vercel Hobby's 12 functions, so the ESPN proxy became a new mode on an existing function instead of a new one.

  3. Wrote and shipped the Android TV app

    A small Kotlin app: a foreground service (an Android 14 requirement), a transparent WebView that can't take focus or touches, restart on boot, retry when Wi-Fi drops, and an overnight reload to pick up site deploys. Compiled and checked in CI; GitHub Actions publishes the APK as a release.

  4. Installed it the hard way

    Sideloading meant wireless debugging and adb. The home router silently blocked device-to-device traffic (client isolation), so the install went over a phone hotspot, which only handed out IPv6 addresses, so pairing ran over IPv6. Then one appops command granted the overlay permission that Google TV's settings won't expose.

  5. Iterated from real Saturdays

    Added a full-screen scoreboard, a top or bottom ticker, compact mode, last play, timeouts, win %, TV network, and a gold flash when a bet flips between covering and not. Fixed a real bug: ESPN rejects date ranges for college, which made multi-day slates look unplayed.

  6. Matched my social graphics

    Rebuilt each game card around the same layout as the tiles I post: Vegas vs. YCPR spread and total, projected cover and total call, projected score, and after the final the ATS and O/U results with a ✓/✗ on my calls.

  7. Expanded scope

    Added NFL mode, a field-position bar, a live cover-probability model, an “Expand” button that shows the site's matchup pop-up on the TV, Sleeper fantasy, and pool picks graded with each pool's own rules.

Engineering highlights

The interesting parts

Live cover probability

ESPN publishes win % but nothing against the spread, so I model it: final margin ≈ score now + the pregame line scaled by time left, with uncertainty shrinking as the clock runs.

P(cover) = 1 − Φ((−line − μ) / (σ·√t))
μ = margin + spread_exp · t

Spoiler delay

Streams run 30–90 s behind live. Every scoreboard snapshot is queued with a timestamp, and the bug renders the newest one older than the chosen delay, so scores, bet flips and flashes all land with the play on screen.

Zero-cost data

No paid API calls during games. ESPN's free scoreboard goes through one function cached for 10 s at the edge, so every screen shares one upstream request. Lines, locks and bets are read once and never polled.

Ships like a website

The Android app is just a see-through window around /overlay. Every feature after install was a Vercel deploy; the TVs pick it up on a reload. The heavy matchup pop-up loads only when expanded.

Fit-to-screen layouts

Every size is a multiple of one unit, 1% of the screen height, so the phone preview is an exact miniature of the TV. Full screens measure their own overflow and scale down until everything fits.

Grading that matches the source

Pool picks reuse each pool's own rules and lines: the pool's line, a Vegas fallback where the pool uses one, or straight up. The bug and each pool's page can't disagree.

Problems solved

Challenges

Problem
Solution
Google TV won't grant “display over other apps” to sideloaded apps
Granted once with adb shell appops; the app restarts itself after every reboot
Home router blocked the laptop from reaching the TV
Diagnosed with ping and nc; paired over a phone hotspot using the TV's IPv6 address
Vercel Hobby allows 12 serverless functions; 11 were taken
NFL, ESPN and Sleeper became modes on an existing function, and saves went through another
ESPN's college scoreboard errors on date ranges
Fetch each day separately, so one bad day doesn't blank the board; stored finals fill any gaps
ESPN often leaves possession and yard line empty
Verified against live games and fell back to the end of the last play, where both are always present
Sleeper's player list is 15 MB, too much for a TV
Trimmed to about 100 KB on the server and cached at the edge for a day
